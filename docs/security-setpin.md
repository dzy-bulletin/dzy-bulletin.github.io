# 第一次設密碼缺口（2026-10-14）

## 問題（已在本機假資料重現）
- `roster`（不用登入）回傳每位在職同仁的 `hasPin`，外人看得出誰還沒設密碼。
- `setPin` 只檢查「這人還沒設過密碼」與密碼強度，不確認操作者是本人，成功就發登入 token。
- 重現（`js/mock.js` 假資料，scratchpad `repro.js`）：外人取名單 → 挑 hasPin=false 的 S-013 → setPin 成功、看到 5 則公告 → ack 代簽成功 → 本人再來 setPin 回 `HAS_PIN`。
- 同樣缺口也在「重設密碼」：主管按重設後，那人回到沒密碼狀態，誰先搶到誰設。
- 沒有限流：只有 lineLogin 有每 IP／全體限流；setPin、login、roster 沒有。
- 無法事後追查：staff 沒有「密碼設定時間」欄位；伺服器紀錄只有「時間 動作 毫秒 ok/錯誤碼」，沒有是誰、沒有 IP。

## 修法選項
| | 做法 | 能不能根治 | 代價 |
|---|---|---|---|
| A（推薦） | 有綁打卡 LINE 的人：第一次設密碼要先從 LINE 選單進來（LINE 驗證過才給設）。沒綁 LINE 的人、以及「重設密碼」：主管按按鈕產生一次性 6 位數啟用碼，同仁輸入啟用碼＋新密碼。另拿掉 roster 的 hasPin、setPin 加限流 | 能 | 沒綁 LINE 的人要等主管給碼 |
| B | 全員都用主管給的啟用碼 | 能 | 每位沒密碼的人主管都要發一次碼 |
| C | 只拿掉 hasPin＋限流 | 不能（外人仍可逐一試） | 最小 |

## 選 A 時的細節（待確認）
- 啟用碼：6 位數、用一次就作廢、有效期待定（推薦 7 天）、輸錯 3 次作廢要重發；資料庫只存雜湊。
- 主管畫面：同仁名單每人一顆「產生啟用碼」；「重設密碼」改成清掉密碼＋同時產生啟用碼，碼只顯示一次。
- 選名字畫面：沒設密碼的人點進去 → 顯示「請從 LINE『鼎兆元打卡』選單點佈告欄，或請主管給你啟用碼」，有啟用碼欄位。
- LINE 登入後若沒設密碼：照常進佈告欄（不強迫設），設定頁可選擇補設密碼。
- 已設好的密碼：先唯讀查正式資料有無可疑，再決定個別重設。
